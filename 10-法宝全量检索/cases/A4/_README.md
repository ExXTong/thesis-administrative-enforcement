# cases/A4/ 数据说明（给下游分析者）

## 怎么读这些文件

每个 `*.json` = **一次法宝调用**的原始返回，字段：

| 字段 | 含义 |
|---|---|
| `query` | 本次实际发出的检索式（`fulltext` 关键词、`startLastInstanceDate`/`endLastInstanceDate` 区间、`court`） |
| `total` | **法宝报告的该检索式下真实总数** |
| `count` / `cases` | 实际返回的条数（法宝硬上限 20 条，无翻页） |
| `cases[].案号/标题/法院/审结日期/查明/本院认为/裁判依据/裁定结果/法宝链接` | 案例字段 |

### 三条必须注意的判读规则

1. **只有 `total <= 20` 的文件才是「完整切片」**（该区间已全部拿到）。
   `total > 20` 的文件**只含前 20 条**，是残缺的，不要当成全量。
   完整切片的并集 = 已完整覆盖的区间，见 `_未拿全清单.md`。
2. **文件名里带法院字样的文件请全部忽略**（如 `*__基层人民法院__*.json`）。
   这是失效维度：12 次调用全部返回 `total=0 / count=0`，文件是空的。
3. **去重请用 `法宝链接`，不要用 `案号`。**
   法宝存在「同一案号、不同链接」的多条记录（已实测 57 处），按案号去重会误删。

## 为什么没拿全

见 `_未拿全清单.md`：主因是 `--court` 维度失效（实测 12 次全 0）+ 案件在日期上高度聚集
（单日可达 30~34 条），日期切到「单日」后仍 >20 的区间已无更细维度可用。
